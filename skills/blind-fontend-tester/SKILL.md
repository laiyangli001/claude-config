  盲测前端自动化工程师。模拟无法直接看到画面的测试工程师，通过浏览器

  编写临时脚本，最终生成可回归执行的测试代码。

## 触发条件

用户描述一个前端操作场景（如"打开登录页，输入账号密码，点击登录，验证跳转"）。

## 执行步骤

### 第 1 步：理解需求

确认用户描述的前端场景，明确以下信息：
- **目标 URL**：要测试的页面地址
- **操作步骤**：需要执行哪些交互（点击、输入、选择等）
- **验证点**：每一步的预期结果（弹窗出现、页面跳转、数据更新等）

### 第 2 步：导航与初始化

打开目标 URL，等待页面加载完成。

```text
🌐 正在打开: https://example.com/login
```

### 第 3 步：分步操作循环

对每个交互步骤执行以下流程：

1. **获取页面状态** — 优先使用可访问性树获取当前页面结构
2. **描述预期** — 用文字说明预期结果
3. **执行动作** — 点击、输入等操作，等待页面反应
4. **预期检测** — 检测页面是否符合预期

#### 正常流程

- 默认超时 15 秒（复杂页面 30 秒）
- 匹配成功 → 标记 ✅ 并记录元素选择器
- 选择器优先级：`data-testid` > `id` > `aria-label` > 稳定文本

#### 超时 → 异常恢复

```
⚠️ 等待超时（15s），执行异常恢复：
  ① 截图保存当前画面
  ② 获取 DOM 摘要，定位问题
  ③ 编写临时 page.evaluate 脚本强制操作
  ④ 重试一次
```

连续 2 次失败 → 暂停并向用户报告阻塞，请求决策：

```text
❌ 无法完成步骤：[具体步骤]
   原因：[具体问题，如选择器失效/元素被遮挡]
   建议方案：
   [1] [方案一]
   [2] [方案二]
   请选择或指定其他方式
```

### 第 4 步：视觉需求兜底

当自动检测无法确认页面真实渲染时，主动请求截图：

```text
📷 无法通过 DOM 确认页面状态，正在截图...
```

优先截取程序窗口并获取窗口名，将截图作为理解页面的依据。

### 第 5 步：长耗时操作监控

上传、长加载等操作将超时设为 60 秒：

- 持续检测进度条、加载图标、成功提示
- 卡死时提示用户手动完成

```text
⏳ 上传超时（60s），无法自动完成
   请您手动完成上传，完成后我会继续执行后续步骤
```

### 第 6 步：编译回归测试

所有步骤验证通过后，将流程转换为 Playwright 测试脚本（TypeScript）：

```typescript
import { test, expect } from "@playwright/test";

test("generated test", async ({ page }) => {
  // 步骤 1：打开页面
  await page.goto("https://example.com/login");
  await expect(page.locator("#username")).toBeVisible();

  // 步骤 2：输入账号
  await page.locator("#username").fill("test@example.com");

  // ...
});
```

- 写入 `.spec.ts` 文件
- 执行 `npx playwright test` 运行测试
- 若失败，根据错误定位修改选择器或等待策略，自动重试直至通过

输出测试报告摘要：
