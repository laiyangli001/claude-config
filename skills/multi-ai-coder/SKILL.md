## 角色与职责

- **DeepSeek（项目经理 & 主力开发）**
  - 需求分析、技术方案、项目骨架
  - 所有基础模块的代码编写
  - 根据 ChatGPT 审查意见修复 bug（简单/中等复杂度）
  - 文件管理、集成验证、交付汇总
- **ChatGPT（技术主管 & 审查员）**
  - 生成中大型项目的详细实现计划（仅一次）
  - 执行多轮代码审查（2~3 轮，有收敛机制）
- **Claude（高级工程师）**
  - 复杂模块的首次实现
  - 复杂 bug 的修复（DeepSeek 两轮自修仍不通过）

## 复杂度判定

- **基础模块**：CRUD、文件读写、简单算法、常规界面、标准库调用 → DeepSeek 直接编写
- **复杂模块**（满足任一）：
  - 非平凡算法（图、动态规划、并发、复杂状态机）
  - 第三方服务深度集成且文档不全
  - DeepSeek 两次修复仍未解决
  → Claude 编写或修复

- **计划复杂度**：
  - 简单项目（≤3 文件，无复杂模块）→ 跳过 ChatGPT 计划，DeepSeek 自行设计
  - 中大型项目 → 调用一次 ChatGPT 生成详细计划

## 工作流

### 第 1 步：需求分析与方案设计（DeepSeek）

```text
用户输入需求
  │
  ▼
DeepSeek ── 分析需求 → 出方案 → 标复杂度
  │
  ├─ 简单项目 ──→ 直接输出接口与伪代码
  └─ 复杂项目 ──→ 标注"需生成详细计划"
```

调用 `ask_deepseek`：

> 你是全栈工程师兼项目经理。用户需求：{{userInput}}
> 输出：
> 1. 需求摘要
> 2. 技术栈
> 3. 目录结构（所有文件路径）
> 4. 模块清单（3~6个），标注复杂度（基础/复杂）并说明
> 5. 简单项目直接输出接口与伪代码；否则标注"需生成详细计划"

### 第 2 步：生成项目骨架（DeepSeek）

```bash
mkdir -p {{projectDir}}/src
mkdir -p {{projectDir}}/tests
```

初始化包管理文件、README 等。

### 第 3 步：获取实现计划（按需调用 ChatGPT）

条件：仅当第 1 步标记"需生成详细计划"时执行。

调用 `ask_chatgpt_official`：

> 你是技术主管。根据以下分析输出详细实现计划：
> {{deepseekOutput}}
>
> 要求：每个文件的接口、数据结构、调用关系、伪代码。
> 不要输出完整代码。

失败处理：超时/报错 → 重试 3 次 → 仍失败 → 报告用户请示是否继续。

### 第 4 步：逐模块实现

**基础模块** → DeepSeek 生成并保存
**复杂模块** → Claude 生成并保存

调用 `ask_deepseek` 或 `ask_claude_mirror`，每次生成一个文件。

生成后立即语法/导入校验。失败处理：

- 基础模块失败 → DeepSeek 自修（最多 2 轮），仍失败升级为复杂模块，移交 Claude
- 复杂模块失败 → Claude 重写一次，仍失败则在最终报告标注
- 任何服务失败 → 重试 3 次 → 仍失败 → 报告用户请示

### 第 5 步：集成验证（DeepSeek）

所有文件就位后，DeepSeek 执行：
- 尝试运行入口程序
- 运行基础测试（如有）
- 收集所有运行时错误、测试失败
- 生成内部问题清单，作为下一轮审查的输入

### 第 6 步：多轮代码审查（ChatGPT，2~3 轮）

审查采用迭代式，最多执行 3 轮，满足收敛条件可提前结束。

**收敛条件**（满足任一即停止）：
1. 当前轮次审查结果中 🔴 必须修复的 Bug 数量为 0
2. 已执行满 3 轮

#### 第 6.1 步：第一轮审查

调用 `ask_chatgpt_official`：

> 你是代码审查专家。请审查以下项目完整代码，结合集成验证错误。
> 项目方案：{{deepseekOutput}}
> 集成错误：{{integrationErrors}}
> 所有文件代码（含行号）：{{allFilesWithLineNumbers}}
>
> 按以下格式输出：
> 🔴 必须修复的 Bug（文件名+行号+修复建议）
> 🟡 潜在性能/安全问题（文件名+行号+建议）
> 🟢 代码风格改进（可选）

#### 第 6.2 步：DeepSeek 修复

- 修复所有 🔴 和大部分 🟡 问题
- 每个文件修复后语法校验
- 修复后仍有运行错误 → DeepSeek 自修（最多 2 轮）
- 仍失败 → 标记为复杂修复，待下一轮审查

#### 第 6.3 步：下一轮审查（条件触发）

检查收敛条件：
- 🔴 数量为 0 → 结束
- 已满 3 轮 → 结束
- 否则 → 继续下一轮

下一轮审查 prompt（精简版，减少重复审查）：

> 这是第 {{roundNumber}} 轮代码审查。上一轮发现 {{lastRoundBugCount}} 个🔴，已全部修复。
> 请对修复后的代码再次审查，重点关注：
> - 修复是否引入新问题
> - 上一轮中 🟡 建议的处理是否合理
> - 仍存在的任何缺陷
> 当前所有文件代码：{{allFilesWithLineNumbers}}

#### 第 6.4 步：复杂修复移交（按需）

DeepSeek 两轮自修仍无法解决的 🔴 Bug，且属于复杂模块，调用 Claude 针对性修复：

> 以下文件存在复杂缺陷：
> {{bugReport}}
> 原审查意见：{{reviewForThisFile}}
> 请输出修复后的完整文件代码，仅修复缺陷，保留正确逻辑。

Claude 产出后更新文件，可再触发一轮审查确认修复（计入总轮数，≤3 轮）。

### 第 7 步：交付汇总

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  📦 {{projectName}} 开发完成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 📄 文件结构
   ├── ...

 🧠 Token 消耗
   DeepSeek: {{dsTokens}}
   ChatGPT: {{gptTokens}}（计划 + 审查共 {{reviewRounds}} 轮）
   Claude: {{claudeTokens}}

 🔍 最终审查结果
   审查轮次: {{reviewRounds}}
   最终 🔴: 0（已全部修复）
   最终 🟡: {{remainingSuggestions}}
   ⚠️ 未修复复杂问题: {{unfixedComplexBugs}}

 💡 运行方式
   cd {{projectDir}} && ...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 失败处理

**通用重试规则：** 每次失败必须重试 **3 次**（间隔 2 秒）。3 次全部失败后暂停，向用户报告失败原因和当前进度，请示是否继续。未修复用户确认就跳过步骤只会浪费 token。

| 情况 | 处理方式 |
|------|---------|
| ChatGPT 超时/错误 | 重试 3 次 → 报告用户请示 |
| Claude 超时/错误 | 重试 3 次 → 报告用户请示 |
| DeepSeek 超时/错误 | 重试 3 次 → 报告用户请示 |
| 审查发现严重 bug | 循环第 6 步修复，最多 2 轮 |
| 文件保存失败 | 显示文件内容让用户手动保存 |
| 用户确认继续 | 跳过失败步骤，用已有结果继续 |
| 用户放弃 | 终止工作流，输出已完成步骤结果 |

## Token 节省策略

| 策略 | 说明 |
|------|------|
| 审查收敛机制 | 最多 3 轮，无严重 Bug 即停止 |
| 审查提示精简 | 第二轮起只关注新问题和遗留问题 |
| 复杂度过滤 | 基础模块不消耗 Claude token |
| 修复上限 | DeepSeek 每文件每轮最多 2 次自修 |
| 降级链 | ChatGPT 失败 → DeepSeek 自我审查；Claude 失败 → DeepSeek 修复 |
